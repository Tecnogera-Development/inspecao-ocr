# Runbook v1.1 — operação cotidiana

Guia rápido para operadores e devs. Cobre disparar pipeline, acompanhar progresso, abrir relatório, consultar custo e debug básico.

## URLs e credenciais

- **Portal** (operador): `http://localhost:3000` (em produção: `http://<vps>:3000` quando IAVS-050 fechar)
- **API direta** (integração): `http://localhost:8000`
- **Swagger**: `http://localhost:8000/docs`
- **Healthcheck**: `http://localhost:8000/health`

Login do portal: usuário criado via `python -m app.cli create_user`. Sessão dura 8h, cookie httpOnly Secure SameSite=Lax.

## Disparar uma análise

### Via portal (operador)
1. Login.
2. Click "Nova análise" (header) ou "/run".
3. Digita `checklist_id` (apenas dígitos, formato Sisloc).
4. Click "Executar". Redireciona para a tela de detalhes do job criado.
5. Polling automático a cada 5s atualiza status `pending → running → done`.

### Via curl (integração, debug)
```bash
# precisa de PIPELINE_API_KEY no .env e header X-API-Key
curl -X POST http://localhost:8000/api/v1/pipeline/run \
  -H "X-API-Key: $PIPELINE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"checklist_id":"276800"}'
```

Modo batch (50% off, latência 20min-2h):
```bash
curl -X POST "http://localhost:8000/api/v1/pipeline/run?mode=batch" ...
```
Threshold mínimo: 30 imgs. Abaixo disso retorna 422.

## Acompanhar status

### Portal
- Dashboard: lista paginada com filtros (status, período). Polling 10s quando há jobs em curso, 60s quando tudo idle.
- Cards do topo: total processado no mês, em andamento, com erro, custo total mês.
- Tela de detalhes: cabeçalho com cost/duration, grid de fotos com label + confidence + badge (valid/inconclusive), seção "Inconclusivas" recolhível, botão "Ver PDF".

### API
```bash
curl http://localhost:8000/api/v1/pipeline/jobs/{job_id}
```

## Abrir o PDF

- **Portal**: botão "Ver PDF" → abre nova aba via endpoint `/api/v1/portal/jobs/{id}/pdf` que faz streaming do Dropbox autenticado por sessão. PDF nunca aparece como URL direta no DOM.
- **Diretamente do Dropbox**: caminho em `pipeline_jobs.result_pdf_path` (ex: `/comparativo_de_imagem/276800_<ts>.pdf`).
- **Download local** (debug):
  ```bash
  docker exec tecnogera-ia-visual-api-1 python -c "
  from app.core.config import get_settings
  from app.services.dropbox import DropboxService
  d = DropboxService(get_settings())
  open('/app/data/local_pdfs/out.pdf','wb').write(d.download_image('<path>'))
  "
  ```

## Consultar custo

```sql
-- média dos últimos 5 jobs
SELECT AVG((metrics->>'estimated_cost_usd')::float) AS avg_cost
FROM pipeline_jobs
WHERE status='done' ORDER BY finished_at DESC LIMIT 5;

-- custo total do mês
SELECT SUM((metrics->>'estimated_cost_usd')::float) AS total
FROM pipeline_jobs
WHERE status='done' AND date_trunc('month', finished_at) = date_trunc('month', NOW());

-- custo por checklist no mês
SELECT checklist_id, (metrics->>'estimated_cost_usd')::float AS cost
FROM pipeline_jobs
WHERE status='done' AND date_trunc('month', finished_at) = date_trunc('month', NOW())
ORDER BY cost DESC;
```

Ver também [`cost_query.md`](cost_query.md).

## Re-executar um job que falhou

- Portal: na tela de detalhes do job falho, botão "Re-executar" dispara novo `POST /portal/run` com o mesmo `checklist_id`. Histórico original preservado; novo job aparece como linha separada no dashboard.
- API: simplesmente chamar `/pipeline/run` novamente com o mesmo `checklist_id`. Job antigo em `failed` fica como está.

## Logs

```bash
docker logs tecnogera-ia-visual-api-1 --tail 100 --follow
docker logs tecnogera-ia-visual-portal-1 --tail 50
```

Logs estruturados em JSON, com `job_id` em cada linha relevante. Rotação configurada: 10MB × 5 arquivos por container (via `logging.options` no compose).

## Alertas (jobs failed)

Cron `*/15 * * * *` executa `scripts/alert_failed_jobs.py`. Se `> ALERT_FAILED_JOBS_THRESHOLD` (default 3) jobs `failed` na última hora, escreve linha JSON em `/var/log/tecnogera/alerts.log` + envia email se `ALERT_EMAIL_TO` configurado e `ssmtp` disponível.

Setup detalhado: [`alerts.md`](alerts.md).

## Backup

Cron diário 03:00 (`scripts/backup_postgres.sh`): `pg_dump | gzip` para `/var/backups/tecnogera/`. Retenção local 2 dias.

> v1.1: backup é **somente local** na máquina/VPS. Upload para Dropbox foi removido aguardando scope `sharing.write` (IAVS-056). Em produção isso é risco — restore depende da máquina não falhar.

Detalhes: [`backup.md`](backup.md). Procedimento de restore manual: ver `restore.md` (a escrever quando IAVS-054 rodar).

## Variáveis de ambiente principais

| Var | Default | Função |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | Modelo 1 + Modelo 3 |
| `DROPBOX_*` | — | App credentials + refresh token |
| `PIPELINE_API_KEY` | None | Auth do endpoint `/pipeline/*` (integração). Pode ser `None` em dev. |
| `SESSION_SECRET` | dev default | Assinatura de cookies do portal. **Trocar em produção.** |
| `REPORT_MODEL` | `claude-haiku-4-5` | Modelo do report (A3). Para rollback: `claude-sonnet-4-6`. |
| `REPORT_GENERATOR` | `hybrid` | `hybrid` (A2) ou `legacy` (rollback). |
| `EMIT_QUALITY_SCORE` | `false` | Liga emissão de `quality_score` no Modelo 1. |
| `BATCH_MIN_IMAGES` | `30` | Threshold para aceitar `?mode=batch`. |
| `ALERT_FAILED_JOBS_THRESHOLD` | `3` | Failed jobs/hora antes de alertar. |
| `ALERT_EMAIL_TO` | None | Destino do email de alerta (precisa `ssmtp`). |

|---|---|---|---|
| Modelo 1 (Classifier) | Claude Sonnet 4.6 Vision | Classificar foto → campo Sisloc | ~$0.96/checklist sync, ~$0.48 batch |

## Troubleshooting

| Sintoma | Provável causa | O que olhar |
|---|---|---|
| Portal mostra "404 Not Found" navegando | Rota inexistente no React Router | URL deve ser `/`, `/login`, `/run`, `/jobs/<uuid>` |
| Login falha | User não criado, senha errada, sessão expirou | `python -m app.cli create_user`; ver `SELECT * FROM users` |
| Job fica em `running` para sempre | API restartou no meio do pipeline; recovery hook marca como `failed` na próxima subida | `docker logs api`; query `pipeline_jobs WHERE status='running' AND updated_at < now() - interval '30 min'` |
| Job falha com `ValidationError second_best_*` | LLM emitiu XOR em campo opcional (regressão pós saneamento) | Verificar se commit `6d4791b` está no HEAD |
| PDF link 404 no portal | `result_pdf_path` é path Dropbox, não URL HTTP | Confirmar JobDetailPage usa `/api/v1/portal/jobs/:id/pdf` (commit `ce32d17`) |
| Pipeline sem custo (`estimated_cost_usd: null`) | Job rodou antes do IAVS-049 ou usage não chegou | Ver `metrics` JSON; aceitar para jobs antigos |
| `403 Forbidden` em `POST /portal/run` | CSRF token ausente | Frontend deve ler `<meta name="csrf-token">` ou `GET /api/v1/portal/csrf` |
| Dropbox 401 | refresh token expirou | `python scripts/dropbox-auth.py` para renovar |
